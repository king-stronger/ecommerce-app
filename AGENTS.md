# AGENTS.md — ecommerce-app

SvelteKit storefront for `ecommerce-api`. Production-ready; prefer small, low-risk changes.

## Stack

- **App**: SvelteKit 3 (Svelte 5 runes) · Vite 8 · `@sveltejs/adapter-cloudflare`
- **UI**: Tailwind 4 · shadcn-svelte (vega) · bits-ui · Lucide · fonts Inter + Libre Baskerville
- **API client**: `@hey-api/openapi-ts` → `src/lib/api/client` (fetch SDK, credentials included)
- **Auth**: `better-auth` Svelte client (`adminClient` plugin) against the API origin
- **Lint/format**: ESLint + Prettier (svelte + tailwind plugins)
- **Package manager**: pnpm
- **Alias**: `#lib` / `#lib/*` → `src/lib` (see `package.json` `imports` + `tsconfig` paths)

There is **no** TanStack Query in this repo. Data loading uses SvelteKit `+page.server.ts` loaders and direct hey-api SDK calls in components.

## Layout

```
src/
  env.ts                 # SvelteKit public env (`API_URL`); do not treat as dead code
  lib/
    api/hey-api.ts       # Client runtime config (baseUrl, credentials, Workers service binding)
    api/client/          # GENERATED — do not edit by hand
    auth-client.ts
    admin.ts / catalog.ts / cart-count.svelte.ts / utils.ts
    components/          # App components + ui/* (shadcn)
  routes/                # Storefront + /admin + /compte + /panier + /commande + /commandes
static/
openapi-ts.config.ts     # hey-api input: local API `/docs`
```

## Commands

| Command        | Purpose                                                   |
| -------------- | --------------------------------------------------------- |
| `pnpm dev`     | Vite dev server                                           |
| `pnpm build`   | `wrangler types --check` + Vite/Cloudflare build          |
| `pnpm deploy`  | `pnpm build` then `wrangler deploy`                       |
| `pnpm preview` | Preview built Worker locally                              |
| `pnpm check`   | Wrangler types check + `svelte-kit sync` + `svelte-check` |
| `pnpm lint`    | Prettier `--check` + ESLint                               |
| `pnpm format`  | Prettier write                                            |
| `pnpm gen`     | Regenerate `worker-configuration.d.ts`                    |
| `pnpm gen:api` | Regenerate OpenAPI client (API must serve `/docs`)        |

No test runner / test scripts are configured in this package.

## Conventions

- Public env: only `API_URL` (see `src/env.ts`, `.env.example`). Inlined at build; use `.env` locally and tracked `.env.production` for production URL.
- Always call the API with cookies (`credentials: 'include'` is set in hey-api + auth client).
- SSR on Cloudflare uses the `API` **service binding** when present (`src/lib/api/hey-api.ts`) — workers.dev cannot fetch another workers.dev URL publicly (error 1042).
- New UI primitives: prefer existing `#lib/components/ui/*` or `pnpm dlx shadcn-svelte@latest add …` per `components.json`.
- Admin UI lives under `/admin` and relies on Better Auth session + admin role (not Scalar-only).
- Currency display helpers treat API amounts as integer cents (`#lib/catalog`).

## Do not edit by hand

| Path                        | Regenerated by                                       |
| --------------------------- | ---------------------------------------------------- |
| `src/lib/api/client/**`     | `pnpm gen:api` (API at `openapi-ts.config.ts` input) |
| `worker-configuration.d.ts` | `pnpm gen` / `wrangler types`                        |
| `.svelte-kit/**`            | SvelteKit sync/build (local artifact; not source)    |

`src/env.ts` looks unused to static analyzers: keep it — SvelteKit loads it for `$app/env/public`.

## Pitfalls

- Run `pnpm gen:api` only while the API OpenAPI doc is reachable; default input is `http://localhost:8787/docs`.
- After a failed/partial `pnpm build`, stale `.svelte-kit/output` or `.svelte-kit/cloudflare` can make `svelte-check` report hundreds of false errors. Remove those dirs and re-run `pnpm check`.
- Do not invent storefront features the API does not expose (payments charge, search, wishlist, reviews). See `PRODUCT.md` for product boundaries (some admin UI exists in-app despite older PRODUCT notes).

## Change rules for agents

1. No style-only refactors; do not swap stack/deps without a concrete need.
2. Do not rewrite working routes or regenerate the API client unless the OpenAPI surface changed.
3. Prefer extending existing `#lib` helpers and route patterns.
4. After changes: `pnpm check`, `pnpm lint`, `pnpm build`.
